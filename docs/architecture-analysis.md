# 模型结构分析与潜在问题

> 记录于 2026-07-09，基于与 Stable Diffusion 结构的对比分析。

---

## 一、tanh 饱和问题（已修复）

### 问题描述

VAE decoder 最后一层使用 `torch.tanh(h)` 将输出钳制在 [-1, 1]。

### 触发链路

```
扩散 1000 步反向采样
  ↓ 每步预测 x₀（潜空间）
最终潜变量 ≈ encoder 输出 + 累积去噪误差
  ↓
vae.decode(z_final)
  ↓ 中间层激活值 >>3 或 <<-3
tanh 饱和 → 输出全部为 ±1
  ↓
PNG 保存时 clip 到 [0,255] → 纯黑白二值图像
  ↓
纤维细节全部丢失
```

### 根因

VAE 训练时 decoder 看到的潜变量来自 encoder（有 KL 约束，分布受控趋于 N(0,I)）。但扩散采样产出的潜变量不受约束，分布稍有偏移就会触发 tanh 饱和。这也是 Stable Diffusion 等主流 LDM 的 decoder 不使用 tanh 的原因。

### 修复

`improved_diffusion/vae.py:134` — 将 `torch.tanh(h)` 改为直接输出 `h`（线性输出）。

### 副作用

旧 VAE 是用 tanh 训练的，去掉 tanh 后 decoder 最后一层权重不再适配，需要从头重新训练 VAE。

## 二、与 Stable Diffusion 的结构差异及潜在问题

### 对比总表

| | **Stable Diffusion** | **本模型** |
|---|---|---|
| **空间维度** | 2D (H×W) | 3D (D×H×W) |
| **VAE 压缩** | 8×, latent=4ch | 4×, latent=8ch |
| **UNet 下采样** | stride=(2,2) 全维度 | stride=**(1,2,2)** Z轴不降采样 |
| **通道倍数** | (1, 2, 4, **8**) | (1, 2, 4, **4**) |
| **条件注入** | 交叉注意力 (cross-attn) | 通道拼接 `[x_t, z_init, mask]` |
| **VAE 状态** | **冻结** | **可训练** |
| **训练数据** | LAION-5B (数亿) | 64 个 volume |
| **采样引导** | CFG (scale=7.5) | 无 |
| **已知区域约束** | 像素空间直接替换 | 潜空间 `denoised_fn` |

---

### 问题一：Z 轴不下采样 — 最严重的结构缺陷

**现状**：UNet 的 downsample stride 为 `(1, 2, 2)`，只对 H 和 W 降采样，D 轴全程不变。

```
    层级      潜空间分辨率(D×H×W)    通道
    ─────────────────────────────────────
    L0        64 × 256 × 256           64
    L1        64 × 128 × 128          128
    L2        64 ×  64 ×  64          256
    L3        64 ×  32 ×  32          256
```

**后果**：

- **Z 轴没有多尺度特征**：模型能学到 XY 平面的 4 个粒度级别，Z 轴只有完整 64 深度的单一粒度
- **3D 卷积在 Z 方向感受野浅**：每层 3³ 卷积核在 Z 上只能看到 3 个体素，堆叠 2-3 个残差块后有效感受野仍然很小
- **无法学习纤维沿 Z 轴的长程结构**：纤维通常贯穿多张切片，但模型缺乏沿 Z 轴的层次化理解
- **3D attention 效率差**：Attention 的计算量是 O((D×H×W)²)，depth=64 时深层的 attention 极其昂贵，且模型难以学到有意义的 attention pattern（因为 Z 方向没有空间压缩）

**修复方向**：将 UNet 下采样改为 stride=(2,2,2)（或至少在中间层对 Z 降采样），让 Z 轴和 XY 轴获得对称的多尺度处理。代价是潜空间的 Z 维度减小，需要确保 VAE 压缩后的 64 深度能被 2 整除。

---

### 问题二：条件注入方式 — 通道拼接 vs 交叉注意力

**现状**：条件信号通过 Channel Concatenation 注入 `th.cat([x_t, z_init, mask], dim=1)`。

**SD 的做法**：交叉注意力 Cross-Attention。

| | 通道拼接 | 交叉注意力 |
|---|---|---|
| **机制** | 固定卷积核混合 | Q(待生成)×K(条件)→注意力权重×V(条件) |
| **空间交互** | 均匀，无选择 | 自适应，每个位置可关注条件的不同位置 |
| **信息利用** | 被动 | 主动查询 |

**对 outpainting 任务的影响**：

- Outpainting 的本质是"已知区域 → 未知区域"的空间对应关系。交叉注意力天然可以让模型学习"未知区域的每个位置应该参考已知区域的哪个位置"
- 通道拼接依赖固定 3³ 卷积核来建立这种对应——一个卷积核只能看到 3×3×3 的邻域，要建立 256³ 体积中"对角角落"与"中心"的联系，需要非常深的网络
- Mask 只标记"哪里已知"，不提供空间位置信息。模型无法区分"这是左上角的已知"和"这是右下角的已知"

**修复方向**：实现交叉注意力条件注入，或者至少加入 positional encoding（坐标位置信息），让模型知道已知区域在体积中的空间位置。

---

### 问题三：VAE 可训练 + 极小数据集 — 训练不稳定

**现状**：VAE encoder + decoder + UNet 同时在 64 个样本上联合训练。

**SD 的做法**：VAE 单独预训练后冻结，扩散模型在固定的潜空间中学习。

**后果**：

```
扩散 loss 梯度 → encoder 更新 → 潜空间持续漂移
    ↓
UNet 面对移动的目标分布 → 学到错误的 denoising
    ↓
decoder 需要 vae_recon_weight 才能跟上 → 两个 loss 目标不一致
    ↓
本质上在同时解两个欠定问题（学习编码 + 学习生成）
```

**修复方向**：
1. 短期：将 VAE 冻结，只训练 UNet（回到标准 LDM 范式）
2. 长期：大幅扩充数据集（×100 以上），再尝试联合训练

---

### 问题四：无 Classifier-Free Guidance (CFG)

**现状**：采样时无条件分支，无 CFG scale。

**SD 的做法**：同时在条件和无条件上训练模型，采样时外推：
```python
pred = unconditional + 7.5 × (conditional - unconditional)
```

**影响**：

- CFG 让模型在"忠实于已知信息"和"创造性生成"之间可调节
- 对于 64 样本的小数据集，CFG 可以抑制模式坍塌——无 CFG 时模型倾向于生成"平均化的模糊输出"
- Outpainting 天然需要 CFG：条件越强（7.5），输出越贴近已知区域的结构；条件越弱（1.0），越可能有创造性变化

**修复方向**：实现 CFG 训练（以一定概率 dropout 条件）和采样。

---

### 问题五：通道倍数 (channel_mult) 缺少最深一层

**现状**：`channel_mult = (1, 2, 4, 4)`

**SD**：`(1, 2, 4, 8)`

| 层级 | 本模型 | SD | 影响 |
|------|--------|----|------|
| L0 | 64 (1×) | 320 (1×) | 初始层 |
| L1 | 128 (2×) | 640 (2×) | |
| L2 | 256 (4×) | 1280 (4×) | |
| L3 | 256 (4×) | **2560 (8×)** | 最深全局层 |

最深层的处理能力直接影响全局结构生成——对 outpainting 来说，"整个体积应该长什么样"的全局理解在这里形成。最深两层通道相同意味着模型在最关键的位置缺少表达力。

**修复方向**：channel_mult 改为 (1, 2, 4, 8)。

---

### 问题六：潜空间 denoised_fn 的工程权衡

**现状**：每步在潜空间强制替换已知区域：
```python
x0 = e_mask × x0 + (1.0 - e_mask) × e_init
```

**SD inpainting 的做法**：在像素空间替换。

**潜在问题**：

- 假设 `e_init` 是已知区域的完美潜表示，但 VAE 重建本身有误差
- 去噪过程中已知区域潜变量被冻结，相邻未知区域潜变量在变化，边界可能产生不连续性
- 潜空间是压缩的、抽象的表征，直接替换部分值是否合理缺乏理论保证

**修复方向**：考虑在像素空间做替换（需要每步 decode→替换→encode，计算成本高但更直观），或简化 VAE 压缩率来缩小潜-像空间差异。

---

### 问题七：Attention 分辨率参数不匹配

**现状**：`attention_resolutions` 的计算使用 `image_size / resolution` 得到 ds 后与 UNet 的比较。

| 配置的 resolution | image_size=256 时对应 ds | UNet 实际 ds (channel_mult=(1,2,4,4)) | 是否生效 |
|---|---|---|---|
| `"32"` (旧配 `"32,16,8,4"`) | 8 | 1, 2, 4, **8** | ✅ 仅最深一层 |
| `"16"` | 16 | — | ❌ |
| `"8"` | 32 | — | ❌ |
| `"4"` | 64 | — | ❌ |
| `"256"` | **1** | 1, 2, 4, 8 | ✅ |
| `"128"` | **2** | 1, 2, 4, 8 | ✅ |
| `"64"` | **4** | 1, 2, 4, 8 | ✅ |

**结论**：必须用 `"256,128,64,32"` 才能让所有 4 层的 attention 都生效。其他值大概率导致部分或全部 attention 层被跳过。

## 三、修复优先级汇总

| 优先级 | 问题 | 当前状态 | 修复方向 |
|--------|------|----------|----------|
| ✅ 已修复 | VAE decoder tanh 饱和 | 已改为线性输出 | — |
| 🔴 P0 | Z 轴不下采样 | stride=(1,2,2) | → (2,2,2) 或混合 |
| 🔴 P0 | Attention 分辨率不匹配 | 大部分层 attention 不生效 | → `"256,128,64,32"` |
| 🔴 P0 | 条件注入方式 | 通道拼接 | → 交叉注意力 或 +位置编码 |
| 🟡 P1 | VAE 可训练 + 小数据集 | 联合训练 | → 冻结 VAE |
| 🟡 P1 | 无 CFG | 正向采样 | → 实现 CFG |
| 🟢 P2 | channel_mult 缺最深一层 | (1,2,4,4) | → (1,2,4,8) |
| 🟢 P2 | 潜空间 denoised_fn | 潜空间替换 | → 考虑像素空间替换 |
